Feature Engineering

Target Class Construction

The target variable is derived from the survey statement: "AI agents have increased my productivity." Responses are encoded into three ordinal classes:

  • Class 0 — Disagree: Strongly disagree or Disagree
  • Class 1 — Neutral: Neither agree nor disagree
  • Class 2 — Agree: Agree or Strongly agree
Python — Target Class Construction 
# Target definition
PRODUCTIVITY_STR = "AI agents have increased my productivity"

agree_cols = [
    "AIAgentImpactStrongly agree",
    "AIAgentImpactSomewhat agree"
]

neutral_cols = [
    "AIAgentImpactNeutral"
]

disagree_cols = [
    "AIAgentImpactSomewhat disagree",
    "AIAgentImpactStrongly disagree"
]

def get_target(row):
    for c in agree_cols:
        if pd.notna(row[c]) and PRODUCTIVITY_STR in str(row[c]):
            return 2

    for c in neutral_cols:
        if pd.notna(row[c]) and PRODUCTIVITY_STR in str(row[c]):
            return 1

    for c in disagree_cols:
        if pd.notna(row[c]) and PRODUCTIVITY_STR in str(row[c]):
            return 0

    return np.nan

df["target"] = df.apply(get_target, axis=1)
df = df[df["target"].notna()].copy()

print("Target value_counts:")
print(df["target"].value_counts().sort_index().to_string())

Filtering Developers

We filter the raw survey to retain only professional, employed developers with valid work experience:

Inclusion Criteria
  • MainBranch == 'Developer by profession'
  • Employment is Employed or Independent contractor / freelancer
  • WorkExp is not null
  • WorkExp > 0
Python — Filtering Developers

def devtype_bucket(s):
    if pd.isna(s) or str(s).strip() == "":
        return "Other"

    s = str(s).strip()

    for bucket, devtypes in BUCKET_ORDER:
        if s in devtypes:
            return bucket

    return "Other"


df["devtype"] = df["DevType"].apply(devtype_bucket)

AI Editor Feature Construction

AI-powered development environments are grouped into a single binary feature to indicate whether a developer has worked with at least one supported AI editor. The resulting has_ai_editor feature is assigned 1 when an AI editor is reported and 0 otherwise.

Python — AI Editor Feature Construction 
AI_EDITORS = [
    "Cursor",
    "Claude Code",
    "Windsurf",
    "Cline and/or Roo",
    "Lovable.dev",
    "Bolt",
    "Aider",
    "Trae",
    "Copilot"
]


def has_ai_editor(s):
    if pd.isna(s) or str(s).strip() == "":
        return 0

    editors = [x.strip().lower() for x in str(s).split(";")]

    return int(any(editor.lower() in editors for editor in AI_EDITORS))


df["has_ai_editor"] = df["DevEnvsHaveWorkedWith"].apply(has_ai_editor)

Handling Missing Values

Missing values are imputed according to the feature type:

Imputation Strategy
  • Numeric values → Mean (rounded where appropriate)
  • Ordinal / Categorical → Mode
  • Relevant variables → Context-aware handling (special cases)
Python — Missing Value Matrix 
# Visualize missing values by employment status
msno.matrix(df.sort_values(by='Employment'))
plt.show()
OUTPUT — Missing Value Matrix

The result showed that missing values in orgsize and remotework shared similar missing patterns related to employment status. Therefore, these variables were not handled by imputing with a value that is common across the entire dataset. So, the missing values were handled by imputing with the frequent observed value within each corresponding employment group respectively.

Data Normalization

Numeric features such as years of experience, task counts, and LLM counts are standardized using RobustScaler, while ordinal features are kept on their explicit integer scale.

Python — Numerical Scaling
